## [blancofw] 上田版 blancoFramework maven リポジトリへのデプロイ方式の変更

### オレオレ maven リポジトリ

上田版 blancoFramework は github pages 上のオレオレ maven リポジトリで公開しています。リポジトリとしてはこのあたりです。

https://github.com/uedaueo/blancofw-maven2/tree/gh-pages-v3

以前はバージョン毎にリポジトリを別にする方針で branch を分けていたのですが、今回から、旧バージョンも生かしておくために、3.x 系と同じ branch に入れます。URL に v3 とか付いてるのはご愛敬。

maven リポジトリとして使う場合は、pom.xml などで以下のように指定して頂ければ使えます。

```
        <repository>
            <id>blancofw</id>
            <name>blancofw maven repos</name>
            <url>https://raw.github.com/uedaueo/blancofw-maven2/gh-pages-v3/</url>
        </repository>
```

### なぜ maven central におかないのか

広く皆さんに使って頂くためには、オレオレではなく maven central に置きなさいよ、と言われそうなんですが、maven central にはすでに本家の igapyon さんが作られたものが置いてあり、私家版を置くとややこしいかなと、、、

https://central.sonatype.com/search?q=jp.igapyon.blanco

「パッケージのプレフィックス変えればいいだけじゃん」とか言われそうですが、はい、その通りなんですが、、、まあ要するに、単にへたれているだけなんですよー(；´Д｀)

### site-maven-plugin の終焉

でまあ、github には site-maven-plugin を使って上げてたのですが。これが長らくメンテされてなくて、まあでもまだ使えるからとか（セキュリティ的にも deploy 時に使うだけだから大丈夫だろうとか）自分に言い訳しながら使ってました。しかし今回、4.x 系に上げるために久しぶりに使ってみたら、ついに github からユーザ情報が取れなくなって、push できなくなってしまいました。

そんなわけで、代替手段をいくつか AI さんに聞いてみたのですけれども、第一のオススメが GitHub Packages と GitHub Actions を使って CI/CD しなさいと。。。いや、まあ分かるんですが。分かるんですけれども、別にそういうのは求めてなくてですね、、、

ただ GitHub Packages くらいなら使ってもいいかな（ていうか今時はそっちを使うべきやろ）とも思ったのですけれど、どうやら Packages は deploy の時だけで無く、ダウンロード時も token が必要だとか。それだと広く一般公開できないじゃーん、となってこれも没。

そんなわけで、maven-scm-publish-plugin で一旦ローカルにリポジトリを pull して、target の下から maven 形式の output を merge して push する方式にしました。

### maven 形式のターゲット出力

pom.xml に以下の記述をすることで、maven の組み込みプラグイン maven-deploy-plugin が deploy ライフサイクルで発動し、target 下に maven 形式のターゲットを出力してくれます。 （これは実は site-maven-plugin 時代も同じ）


```

    <properties>
（中略）
        <git.branchName>gh-pages-v3</git.branchName>
        <git.repositoryOwner>uedaueo</git.repositoryOwner>
        <git.repositoryName>blancofw-maven2</git.repositoryName>
    </properties>

    <distributionManagement>
        <!-- deploy into local repository for github -->
        <repository>
            <id>deploy-repository</id>
            <name>deployRepository</name>
            <url>file:///${project.build.directory}${git.branchName}</url>
        </repository>
    </distributionManagement>

```

### github への push

次に、maven-scm-publish-plugin を設定する事で、target 下に blancofw-maven2 を pull して、target/gh-pages-v3 を merge and push してくれます。ここで、
**ignorePathsToDeleteがないと、既存のバージョンが消されるので注意**が必要です。

手元の環境では ssh 経由で github にアクセスするようにしており、この形式だと毎回なんどか ssh のパスフレーズを聞かれてうざいのですが、.m2/settings.xml が不要になるのでまあいいかと。dapanda 側は現状、作業ディレクトリの隣に maven 用の git リポジトリを手動で clone しておいて、build.gradle のスクリプトで (grgit を使って) merge やら push やらしてます。これも gradle に maven-scm-publish-plugin のような物があれば移行しちゃおうかなあ、、、以前にやったときは見つけられなくて、泣きながら build.gradle にスクリプトを書いたんですよねえ、、、

```

            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-scm-publish-plugin</artifactId>
                <version>3.3.0</version>
                <configuration>
                    <!-- SSH 形式の URL を指定 -->
                    <pubScmUrl>scm:git:git@github.com:${git.repositoryOwner}/${git.repositoryName}.git</pubScmUrl>
                    <scmBranch>${git.branchName}</scmBranch>
                    <content>${project.build.directory}/${git.branchName}</content>
                    <ignorePathsToDelete>
                        <ignorePathToDelete>**</ignorePathToDelete>
                    </ignorePathsToDelete>
                    <checkinComment>Deploy ${project.artifactId} ${project.version}</checkinComment>
                </configuration>
            </plugin>

```
