##  [blancofw] 上田版 blancoFramework / dapandaFramework の今後の予定

世間様で色々セキュリティ問題が炸裂している昨今。

blancoFramework が生成するソースコードはそれ単体で動作するため、生成したソースコードに不備がない限り、JVM の脆弱性などに影響されることはありません。

とはいえ、ながらく version 3（blancoFramework自身のクラスファイルバージョンが55、対応 Apache POI が 5.2.3、一部の生成ファイルで warning が頻出・特に blancoDb）のままだったので、そろそろバージョンアップを図るべき時期かなと。特に blancoDb が生成するファイルの warning（主に Generics 非対応部分が原因）について、そろそろ本気でなんとかしないといけません。 そもそも Java の Generics はバイトコードに反映されないので、自動生成している限り危険性はあまりないはず、ということで放置してましたが、さすがにねえ、、、(；´Д｀)

そんなわけで、blancoFramework については以下の対応を施して version 4 とする予定です。

* blancoFramework 自身の jar クラスファイルバージョンを 65 (Java21) に設定
* blancoFramework のビルドおよび使用時の推奨 Java バージョンを 25 に設定
* Apache POI 6 系に対応
* google-java-formatter の最新版に対応（kotlin 生成時に使用、クラスバージョン 65 で生成されているので、使用時に Java 21 以上が必要）

以下は追々やっていきます。

* 生成されたソースコードのコンパイル時 waring を可能な限り減らす
* blancoFramework 自身の test コードの充実
* blancoFramework が生成したソースコードの test コードを充実
* 使い方や組み込まれている依存関係などのドキュメント整備

特に blancoDb の生成物は Generics 対応するつもりなので、しっかりテストしないと従来の定義書から生成したコードが動かない、とかなりかねないので（むしろ、アプリケーション側が型定義をちゃんと意識せずに書いていたら確実に動かなくなるかも、、、）。

またこれにともない、dapandaFramework もアップデートします。

* blancoFramework の更新、それらに付随する dapanda 側の更新
* micronaut の最新化対応（各プロジェクトで実施）
* 使い方や組み込まれている依存関係などのドキュメント整備

dapandaFramework は blancoFramework を利用した RESTful API 構築 framework です。現在はサーバサイドは micronaut のためのコントローラクラスを生成するようになっています。クライアントサイドでは vuejs + typescript による画面クラスとルーティングの生成をしています。

こちらは micronaut 本体をはじめ、各種ライブラリのサポートを受けているので、dapandaFramework としてというよりは、プロジェクト（アプリケーション）単位でちゃんとアップデート対応していかないといけません。（dapandaFramework から依存性の伝搬はしないようにしていますので、プロジェクト単位で更新する必要があります。）
