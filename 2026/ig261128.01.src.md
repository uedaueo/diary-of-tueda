## [blancofw] うむむ、、、一筋縄ではいかないなあ

[昨日書いたように](./ig261127.01.html)、maven 形式のパッケージを作成するのには  maven-deploy-plugin を使っています。割と一般的な plugin でよく出来ていると思うのですが、ひとつ落とし穴がありました。

### maven-metada.xml

当然ですが、maven リポジトリには複数のバージョンを配置する事ができます。利用者はこれらのバージョンの中から使いたい物（大抵は最新版）を pom.xml や build.gradle などで指定して使うわけです。このときに、バージョンを範囲で指定する事もできます。

```
[3.0,4.0]
```

などとしておけば、常に 3.x 系の最新が取得できるわけです。このとき、maven リポジトリ上に maven-metadata.xml などというファイルが存在していたります。

```
<?xml version="1.0" encoding="UTF-8"?>
<metadata>
  <groupId>blanco.commons.io</groupId>
  <artifactId>blanco-commons</artifactId>
  <versioning>
    <release>4.0.1</release>
    <versions>
      <version>2.1.7</version>
      <version>3.0.2</version>
      <version>4.0.0</version>
      <version>4.0.1</version>
    </versions>
    <lastUpdated>20261127234624</lastUpdated>
  </versioning>
</metadata>
```

こんな感じで、ダウンロード可能なバージョンを指定しておくわけです。これは maven-deploy-plugin が自動で作成してくれるのですが、その際に、前のバージョンがあればそこに新しいバージョンを追記してくれます。**はい、前のバージョンがあれば**、です。

### mvn clean package してた！

今回、maven-deploy-plugin も maven-scm-publish-plugin も作業ディレクトリに target ディレクトリを使用しています。そして、綺麗な状態でデプロイしたいので、毎回 clean しています、、、はい、そうです。clean したら全部消えて「前のバージョン」が無くなってしまいます(；´Д｀)

今回、blancoCommons を 4.0.0 に上げた時点で、maven-metadata.xml には <version>4.0.0</version>しか無くなってしました。普通は別に困らないのですが、blanco は激しく相互参照しているため、たとえば blancoXmlBeans が blancoCommons 4.0.0 を参照していても、その中から blancoValueObject などを参照して、そっちはまだ blancoCommons 3.x を参照していたりします。maven-metadata.xml には 4.0.0 しか書かれてませんから、そこで 3.x 系の blancoCommons が見つからないというエラーが出てしまいました。

そういえばそうだった、、、何年か前に 3.x 系に上げたときにも同じところではまって、deploy するたびにそのツールの maven-metadata.xml（とそのhash値ファイル）を手で書き換えて、とりあえず全部のツールのバージョンアップが終わったら後は知らん、とう方式でやったのでした。

**オレオレmavenリポジトリがメジャーバージョン毎にブランチを変えてた真の理由**は、これだったのね orz

まあでも実のところ、gh-pages で公開しているので、旧ブランチを参照したいときは gh-pages の設定を変えないといけないので、あまり意味はなかったりして、、、そんなわけで、もう少しマシな方法に変更しました。

### 毎回 maven-metada.xml を落としてくる作戦

解説は割愛しますが、小見出しの通り。pom.xml に追記した設定だけあげておきます。
これで、clean しても毎回 prepare-package フェーズで maven-metadata.xml をダウンロードしてくるので、その後の deploy フェーズで maven-deploy-plugin がバージョンの**追記**をしてくれます。

マシ？まあマシでしょ？（格好いいとは言ってないし、異論もみとめます(；´Д｀)）

```pom.xml
<#noParse>
            <plugin>
                <groupId>org.codehaus.mojo</groupId>
                <artifactId>build-helper-maven-plugin</artifactId>
                <version>3.8.0</version>
                <executions>
                    <execution>
                        <id>regex-property</id>
                        <phase>validate</phase>
                        <goals>
                            <goal>regex-property</goal>
                        </goals>
                        <configuration>
                            <name>group.path</name>
                            <value>${project.groupId}</value>
                            <regex>\.</regex>
                            <replacement>/</replacement>
                            <failIfNoMatch>false</failIfNoMatch>
                        </configuration>
                    </execution>
                </executions>
            </plugin>
</#noParse>
```

```pom.xml
<#noParse>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-antrun-plugin</artifactId>
                <version>3.2.0</version>
                <executions>
                    <execution>
                        <id>download-existing-maven-metadata</id>
                        <phase>prepare-package</phase>
                        <goals>
                            <goal>run</goal>
                        </goals>
                        <configuration>
                            <target>
                                <mkdir dir="${project.build.directory}/${git.branchName}/${group.path}/${project.artifactId}"/>
                                <get src="https://raw.githubusercontent.com/${git.repositoryOwner}/${git.repositoryName}/${git.branchName}/${group.path}/${project.artifactId}/maven-metadata.xml"
                                     dest="${project.build.directory}/${git.branchName}/${group.path}/${project.artifactId}/maven-metadata.xml"
                                     ignoreerrors="false"/>
                            </target>
                        </configuration>
                    </execution>
                </executions>
           </plugin>
</#noParse>
```
